> Established BEFORE authoring `run_sgsslam.sh` (user request: "know exactly what the paper tests on and computes"). Sources: the paper (arXiv 2402.03246, ECCV 2024) cross-checked against the repo's own eval code (authoritative for *what is computed*). ## 1. What the paper evaluates on
- **Replica** — the primary benchmark. **8 scenes:** `room0 room1 room2 office0 office1 office2 office3 office4`. GT semantic masks (generated by the authors à la Semantic-NeRF), iMAP camera trajectories. Download: Dropbox (README §Download → Replica). Repo runs each scene via `scene_name` in `configs/replica/slam.py` (680×1200, `num_semantic_classes=101`, `eval_every=5`, `use_gt_poses=False` = real tracking).
- ScanNet (5 scenes: 0000/0059/0106/0181/0207_00) and ScanNet++ (2: 8b5caf3398, b20a261fdf) — secondary; **not needed for the Phase-A gate** (Replica is the headline + has the semantic mIoU table).
- **Rendering metrics are TRAINING-VIEW** (Table 1 caption: "training view rendering on the Replica dataset"). A separate `scripts/eval_novel_view.py` exists for novel-view but is not the headline table.

## 2. The exact metrics (from `utils/eval_helpers.py`, the final eval ~line 584)
All rendering metrics are computed on **silhouette-masked** renders (`weighted_im = im * (silhouette>sil_thres)`), strided over `eval_every=5` frames, averaged:
| Metric | Code | Definition |
|---|---|---|
| **PSNR** (dB) | `calc_psnr(weighted_im, weighted_gt)` (`:679`) | sil-masked rendered vs GT RGB |
| **SSIM** | `ms_ssim(...)` `pytorch_msssim` (`:673`) | ⚠️ **MS-SSIM**, not vanilla SSIM |
| **LPIPS** | `LearnedPerceptualImagePatchSimilarity('alex', normalize=True)` (`:20,676`) | AlexNet LPIPS on sil-masked |
| **Depth-L1** (cm) | `abs(rendered_depth − gt_depth)·valid_mask` mean (`:373-375`) | **rendered vs GT depth** (Replica HAS GT depth) |
| **ATE-RMSE** (cm) | `evaluate_ate → align()` Horn rigid align, translation error (`:161-178,22`) | est vs GT camera trajectory (rigid, no scale — Replica is metric). NB the code returns mean-trans-error under the "RMSE" label |
| **mIoU** (%) | `evaluate_miou` color-based per-class IoU (`:121-158`) | semantic render vs GT; **Table 3 = 4 scenes only** (room0,1,2,office0) |

The repo's own eval is run inside `scripts/slam.py` at the end — **Phase-A uses the method's own eval (paper-faithful), NOT our DDS harness.** (Our DDS harness is for Phase-B / CRCD only.)

## 5. Two distinctions to carry into the benchmark (don't conflate)
1. **Depth-L1 means two different things.** Phase-A (Replica) = rendered-vs-**GT** depth (paper, cm). Phase-B (CRCD) = input-vs-output, no GT (00_COMMON §0 Decision 1). Same column name, different definition by stage.
2. **SSIM.** Phase-A repro uses the repo's **MS-SSIM** (to match the paper's 0.973). Phase-B CRCD uses our `eval_rendering.py` plain SSIM (cross-method-consistent across all 4 methods). So a method's Phase-A SSIM and its CRCD SSIM are not the same estimator — expected.
